# Инструкция по интеграции ESP32-C6 с сервером и Telegram-ботом

## Обзор архитектуры

```

│  ESP32-C6   │─────▶│   Сервер     │◀────▶│  Telegram   │
│  (устройство)│      │ (Spring Boot)│      │     Бот     │
└─────────────┘      └──────────────┘      └─────────────┘
       │                    │                      │
       │ 1. Аутентификация  │                      │
       │───────────────────▶│                      │
```

## Шаг 1: Настройка устройства ESP32-C6

### 1.1 Конфигурационный файл

Файл `data/spiffs/auth_config.json`:

```json
{
  "login": "0006",
  "password": "esp32_device_secret_key",
  "server_url": "http://192.168.1.12:8080/api/v1/device/auth/login",
  "upload_url": "http://192.168.1.12:8080/api/v1/data/upload",
  "command_url": "http://192.168.1.12:8080/api/v1/device/command"
}
```

### 1.2 Загрузка на плату

```bash
cd /Users/ki.a.kuznetsov/IdeaProjects/recorder
pio run --target uploadfs
pio run --target upload
```

### 1.3 Динамическая регистрация

При первом подключении устройство **автоматически регистрируется** на сервере:
1. Плата отправляет POST запрос с `login` и `password_hash` (SHA-256)
2. Сервер создаёт запись в таблице `devices`
3. Сервер возвращает Bearer-токен (срок действия: 24 часа)
4. Токен используется для загрузки записей

**Не нужно предварительно создавать устройство в базе!**

## Шаг 2: Настройка Telegram-бота

### 2.1 Запуск бота

```bash
cd /Users/ki.a.kuznetsov/IdeaProjects/recorder/telegram_bot
python bot.py
```

### 2.2 Команды для работы с устройствами

| Команда | Описание |
|---------|----------|
| `/devices` | Список привязанных устройств |
| `/link_device <логин>` | Привязать устройство к пользователю |
| `/recordings` | Показать записи (включая записи с устройств) |

### 2.3 Сценарий привязки устройства

1. Пользователь входит в бота: `/login`
2. Пользователь привязывает устройство: `/link_device 0006`
3. Сервер связывает устройство с `user_id` пользователя
4. Записи с устройства появляются в `/recordings`

## Шаг 3: Проверка интеграции

### 3.1 Аутентификация устройства

```bash
curl -X POST http://localhost:8080/api/v1/device/auth/login \
  -H "Content-Type: application/json" \
  -d '{"login": "0006", "password_hash": "d9a915d4e78fa8e341008238b343e2eec1864084a61769d1817569cb834c62df"}'
```

**Ответ:**
```json
{
  "success": true,
  "data": {
    "token": "960934b222884651b5aeea3814f2f03d",
    "expires_in": 86400
  }
}
```

### 3.2 Загрузка записи с устройства

```bash
curl -X POST http://localhost:8080/api/v1/data/upload \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: audio/wav" \
  --data-binary @recording.wav
```

**Ответ:**
```json
{
  "success": true,
  "message": "Recording uploaded successfully. Summarization started.",
  "data": {
    "id": "uuid",
    "deviceLogin": "0006",
    "userId": null
  }
}
```

### 3.3 Привязка устройства к пользователю

```bash
# Получаем токен пользователя
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"login": "testuser", "passwordHash": "..."}'

# Привязываем устройство
curl -X POST http://localhost:8080/api/v1/bot/devices/link/0006 \
  -H "Authorization: Bearer <user_token>"
```

### 3.4 Получение записей пользователя

```bash
curl -X GET http://localhost:8080/api/v1/bot/recordings \
  -H "Authorization: Bearer <user_token>"
```

**Ответ включает записи:**
- С `userId = <user_id>` (записи пользователя)
- С `deviceLogin = "0006"` (записи с привязанного устройства)

## API Endpoints

### Устройство → Сервер

| Endpoint | Method | Описание |
|----------|--------|----------|
| `/api/v1/device/auth/login` | POST | Аутентификация устройства |
| `/api/v1/device/command` | GET | Получение команд (polling) |
| `/api/v1/data/upload` | POST | Загрузка записи (Bearer-токен) |

### Telegram-бот → Сервер

| Endpoint | Method | Описание |
|----------|--------|----------|
| `/api/v1/bot/devices` | GET | Список устройств пользователя |
| `/api/v1/bot/devices/link/{login}` | POST | Привязка устройства |
| `/api/v1/bot/devices/unlink/{login}` | DELETE | Отвязка устройства |
| `/api/v1/bot/recordings` | GET | Записи пользователя + устройств |

## База данных

### Таблица `devices`

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | VARCHAR(36) | UUID устройства |
| `login` | VARCHAR(100) | Уникальный логин (например, MAC-адрес) |
| `password_hash` | VARCHAR(255) | Хеш пароля (SHA-256) |
| `user_id` | VARCHAR(36) | Связь с пользователем (NULL если не привязано) |
| `session_token` | VARCHAR(255) | Bearer-токен для аутентификации |
| `session_expires_at` | TIMESTAMP | Время истечения токена |
| `created_at` | TIMESTAMP | Дата регистрации |
| `last_login_at` | TIMESTAMP | Последний вход |

### Таблица `recordings`

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | VARCHAR(36) | UUID записи |
| `user_id` | VARCHAR(36) | Владелец записи (NULL для устройств) |
| `device_login` | VARCHAR(100) | Устройство, загрузившее запись |
| `filename` | VARCHAR(255) | Имя файла на диске |
| `device_info` | VARCHAR(255) | Информация об устройстве |
| `device_ip` | VARCHAR(45) | IP адрес устройства |

## Безопасность

1. **Пароли устройств** — хранятся в виде SHA-256 хеша
2. **Bearer-токены** — генерируются UUID, срок действия 24 часа
3. **Привязка устройств** — только авторизованный пользователь может привязать устройство
4. **Изоляция записей** — пользователь видит только свои записи и записи с привязанных устройств

## Устранение неполадок

### Устройство не может аутентифицироваться

**Проблема:** `HTTP 401 Unauthorized`

**Причины:**
- Неверный `login` или `password` в `auth_config.json`
- Сервер недоступен

**Решение:**
1. Проверьте логи устройства: `pio device monitor`
2. Проверьте логи сервера: `tail -f /tmp/server.log`
3. Убедитесь, что `server_url` правильный

### Записи не отображаются в боте

**Проблема:** `/recordings` показывает 0 записей

**Причины:**
- Устройство не привязано к пользователю
- Записи загружены до привязки

**Решение:**
1. Привяжите устройство: `/link_device 0006`
2. Загрузите новую запись с устройства
3. Проверьте `/recordings` снова

### Ошибка "Устройство не найдено"

**Проблема:** При привязке устройства возвращается 404

**Причины:**
- Устройство ещё не аутентифицировалось на сервере
- Неверный логин устройства

**Решение:**
1. Дождитесь первой аутентификации устройства
2. Проверьте логи сервера на наличие устройства с таким логином
